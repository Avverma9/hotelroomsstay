# 📋 बुकिंग बिज़नेस रूल्स - पूरी जानकारी

सर्वर में बुकिंग के सभी नियम, स्टेटस ट्रांज़िशन और ऑटोमेटेड प्रोसेस की पूरी डॉक्युमेंटेशन।

---

## 🎯 मुख्य बिज़नेस रूल्स

### 1. रूम और नाइट की लिमिट

| शर्त | लिमिट | स्टेटस | एक्शन |
|------|-------|--------|--------|
| रूम | ≤ 3 | **Confirmed** | ऑटोमेटिक अप्रूवल |
| रूम | > 3 | **Pending** | मैनुअल रिव्यू ज़रूरी |
| नाइट्स | ≤ 3 | **Confirmed** | ऑटोमेटिक अप्रूवल |
| नाइट्स | > 3 | **Pending** | मैनुअल रिव्यू ज़रूरी |

**उदाहरण:**
- 2 रूम, 2 नाइट्स → ✅ **Confirmed**
- 4 रूम, 2 नाइट्स → ⏳ **Pending**
- 2 रूम, 5 नाइट्स → ⏳ **Pending**

---

### 2. डुप्लिकेट बुकिंग डिटेक्शन (Enhanced with Same-Day Logic)

सिस्टम एक्टिव बुकिंग्स को चेक करता है - **मोबाइल नंबर** या **ईमेल** से।

| कंडीशन | स्टेटस | कारण |
|--------|--------|------|
| **First Booking** | **Confirmed** | ✅ कोई existing booking नहीं |
| **Second Booking: Same Day + Same City** (any hotel) | **Pending** | ⚠️ Manual review needed - same day same city suspicious |
| **Same Day + Different City** | **Confirmed** | ✅ Travel itinerary - different destinations |
| **Different Day + Same City + Different Hotel** | **Pending** | Standard duplicate rule |
| **Different City** (any day) | **Confirmed** | ✅ Always allowed |

**Same-Day Detection Examples:**

```
📅 User पहली booking करता है: 15 March, Goa में Hotel A → ✅ CONFIRMED

फिर same day (15 March) को नई bookings करता है:

├─ 15 March, Goa में Hotel B     → ⏳ PENDING (second booking same city)
├─ 15 March, Goa में Hotel A     → ⏳ PENDING (second booking same city)  
├─ 15 March, Mumbai में Hotel C  → ✅ CONFIRMED (different city)
└─ 16 March, Goa में Hotel B     → ⏳ PENDING (standard rule)
```

**Business Logic:**
- **पहली booking** हमेशा confirmed होती है (कोई duplicate नहीं)
- **Second booking same day same city** = suspicious (manual review)
- Different city bookings always allowed (travel itinerary)

**एक्टिव बुकिंग्स** = `Confirmed`, `Pending`, `Checked-in` स्टेटस वाली बुकिंग्स

---

### 3. पेमेंट टाइमर (वेरिएबल)

पेमेंट विंडो चेक-इन से कितने दिन पहले बुकिंग की है, उस पर निर्भर करती है:

| बुकिंग कब की | पेमेंट विंडो | ऑटो-कैंसिल (टाइमआउट) |
|--------------|--------------|----------------------|
| **5-7 दिन** पहले | 48 घंटे | 48 घंटे बाद |
| **2-3 दिन** पहले | 24 घंटे | 24 घंटे बाद |
| **1 दिन** पहले | 6 घंटे | 6 घंटे बाद |

**उदाहरण टाइमलाइन:**

```
चेक-इन डेट: 10 मार्च
├─ 3 मार्च को बुकिंग (7 दिन पहले)
│  └─ पेमेंट टाइमआउट: 5 मार्च रात 11:59 बजे (48 घंटे)
│
├─ 8 मार्च को बुकिंग (2 दिन पहले)
│  └─ पेमेंट टाइमआउट: 9 मार्च रात 11:59 बजे (24 घंटे)
│
└─ 9 मार्च को बुकिंग (1 दिन पहले)
   └─ पेमेंट टाइमआउट: 9 मार्च शाम 6:00 बजे (6 घंटे)
```

अगर टाइमआउट के अंदर पेमेंट नहीं हुआ, तो बुकिंग **ऑटो-कैंसिल** हो जाती है और रूम्स वापस इन्वेंटरी में आ जाते हैं।

---

### 4. No-Show लॉजिक

| कंडीशन | स्टेटस चेंज | ट्रिगर |
|---------|-------------|--------|
| बुकिंग स्टेटस = `Confirmed` | → `No-Show` | कस्टमर चेक-इन डेट + 24 घंटे तक नहीं आया |
| चेक-इन डेट + ग्रेस पीरियड निकल गई | → `No-Show` | ऑटोमेटेड (हर 10 मिनट में रन होता है) |

**⚠️ ग्रेस पीरियड: 25 घंटे**
- Same-day booking (आज की तारीख में बुकिंग) को तुरंत no-show नहीं मार्क करता
- चेक-इन डेट के बाद 25 घंटे का ग्रेस पीरियड देता है

**उदाहरण:**
- बुकिंग: 10 मार्च चेक-इन  
- कस्टमर 11 मार्च रात 1:00 AM तक नहीं आया (25 घंटे बाद)
- सिस्टम 12 मार्च को ऑटोमेटिक **No-Show** मार्क करेगा

**Same-Day Booking Protection:**
- अगर आज 10 मार्च को चेक-इन 10 मार्च की बुकिंग करते हैं
- तो तुरंत no-show नहीं होगी, 25+ घंटे का टाइम मिलेगा

## 👥 यूज़र रोल्स और परमिशन

### होटल पार्टनर

**अलाउड एक्शन:**
- ✅ `Confirmed` → `Checked-in`
- ✅ `Confirmed` → `No-Show`
- ✅ `Checked-in` → `Checked-out`

**अलाउड नहीं:**
- ❌ `Confirmed` बुकिंग कैंसिल नहीं कर सकते
- ❌ `Checked-in` बुकिंग कैंसिल नहीं कर सकते
- ❌ `Pending` बुकिंग मॉडिफाई नहीं कर सकते

**कारण:** होटल सिर्फ चेक-इन/चेक-आउट फ्लो मैनेज कर सकते हैं, पेमेंट या कैंसिलेशन नहीं।

---

### Admin / Developer

**अलाउड एक्शन:**
- ✅ **सभी स्टेटस ट्रांज़िशन**
- ✅ कैंसिल की गई बुकिंग्स भी मॉडिफाई कर सकते हैं
- ✅ किसी भी बिज़नेस रूल को ओवरराइड कर सकते हैं
- ✅ पूर्ण सिस्टम एक्सेस

---

### रेगुलर यूज़र (कस्टमर)

**अलाउड एक्शन:**
- ✅ अपनी `Pending` बुकिंग कैंसिल कर सकते हैं
- ✅ अपनी `Confirmed` बुकिंग कैंसिल कर सकते हैं (OTP वेरिफिकेशन से)

**अलाउड नहीं:**
- ❌ `Checked-in` के बाद मॉडिफाई नहीं कर सकते
- ❌ स्टेटस डायरेक्ट चेंज नहीं कर सकते

## ⚙️ ऑटोमेटेड जॉब्स

### ऑटो-कैंसिल जॉब

**फ्रीक्वेंसी:** हर 10 मिनट में

**टास्क:**
1. **Pending बुकिंग्स कैंसिल करना:** `autoCancelAt` टाइम निकल गया हो
2. **No-Show मार्क करना:** `Confirmed` बुकिंग्स जिनकी चेक-इन डेट निकल गई

**ऑटो-कैंसिल पर एक्शन:**
- स्टेटस → `Cancelled`
- रूम्स इन्वेंटरी में रिलीज़
- कैंसिलेशन ईमेल भेजें
- इन-ऐप नोटिफिकेशन बनाएं
- `statusHistory` में लॉग करें

**No-Show पर एक्शन:**
- स्टेटस → `No-Show`
- टाइमस्टैम्प मार्क करें
- इन-ऐप नोटिफिकेशन बनाएं
- `statusHistory` में लॉग करें

**फाइल लोकेशन:** `server/jobs/autoCancelPendingBookings.js`

## 🔧 इम्प्लीमेंटेशन डिटेल्स

### फाइल्स स्ट्रक्चर

```
server/
├── controllers/booking/
│   └── booking.js              # मेन बुकिंग CRUD ऑपरेशन
├── models/booking/
│   └── booking.js              # बुकिंग स्कीमा
├── routes/booking/
│   └── booking.js              # API endpoints
├── jobs/
│   └── autoCancelPendingBookings.js  # ऑटोमेटेड जॉब्स
├── utils/
│   └── bookingRules.js         # बिज़नेस रूल्स इंजन
└── docs/
    ├── BOOKING_RULES.md        # अंग्रेज़ी डॉक
    └── BOOKING_RULES_HINDI.md  # यह फाइल
```

### मुख्य फंक्शन

**`server/utils/bookingRules.js` में:**
- `calculatePaymentTimeout()` - चेक-इन डेट के हिसाब से टाइमआउट कैल्कुलेट करता है
- `checkDuplicateBooking()` - डुप्लिकेट बुकिंग्स डिटेक्ट करता है
- `determineBookingStatus()` - सभी बिज़नेस रूल्स अप्लाई करता है
- `validateStatusTransition()` - रोल-बेस्ड परमिशन वैलिडेट करता है
- `shouldMarkAsNoShow()` - चेक करता है कि बुकिंग No-Show होनी चाहिए या नहीं

**`server/controllers/booking/booking.js` में:**
- `createBooking()` - रूल्स के साथ नई बुकिंग बनाता है
- `updateBooking()` - परमिशन चेक के साथ बुकिंग अपडेट करता है
- `sendCancellationOtp()` - यूज़र कैंसिलेशन के लिए OTP भेजता है
- `verifyCancellationOtpAndCancel()` - OTP वेरिफाई करके कैंसिल करता है

## 📊 स्टेटस डेफिनिशन

| स्टेटस | डिस्क्रिप्शन | इसमें बदल सकते हैं |
|--------|--------------|-------------------|
| **Pending** | पेमेंट का इंतज़ार | Confirmed, Cancelled, Failed |
| **Confirmed** | पेमेंट सक्सेस, बुकिंग एक्टिव | Checked-in, No-Show, Cancelled* |
| **Checked-in** | कस्टमर चेक-इन हो गया | Checked-out |
| **Checked-out** | कस्टमर चेक-आउट हो गया | *(फाइनल स्टेट)* |
| **No-Show** | कस्टमर नहीं आया | *(फाइनल स्टेट)* |
| **Cancelled** | बुकिंग कैंसिल | *(फाइनल स्टेट)* |
| **Failed** | पेमेंट फेल | *(फाइनल स्टेट)* |

*\* Confirmed बुकिंग को कैंसिल करने के लिए यूज़र OTP वेरिफिकेशन ज़रूरी है*

## 🚀 API उदाहरण

### बुकिंग बनाना

```javascript
POST /booking/:userId/:hotelId

Body: {
  "checkInDate": "2024-03-15",
  "checkOutDate": "2024-03-18",
  "numRooms": 2,
  "guests": 4,
  "roomDetails": [...],
  "paymentMode": "online"
}

// सिस्टम ऑटोमेटिक:
// - नाइट्स कैल्कुलेट करता है (3 nights)
// - रूम लिमिट चेक करता है (2 rooms ≤ 3) ✅
// - नाइट लिमिट चेक करता है (3 nights ≤ 3) ✅
// - डुप्लिकेट चेक करता है
// - पेमेंट टाइमआउट कैल्कुलेट करता है
// - स्टेटस रिटर्न करता है: "Confirmed" या "Pending"
```

### बुकिंग अपडेट (होटल पार्टनर)

```javascript
PUT /updatebooking/:bookingId

Body: {
  "bookingStatus": "Checked-in"
}

// सिस्टम वैलिडेट करता है:
// - करंट स्टेटस "Confirmed" है ✅
// - यूज़र रोल "hotel_partner" है ✅
// - Confirmed → Checked-in ट्रांज़िशन allowed है ✅
// - बुकिंग अपडेट करता है
```

### बुकिंग कैंसिल (यूज़र)

```javascript
// स्टेप 1: OTP रिक्वेस्ट करें
POST /booking/:bookingId/cancel/send-otp

// स्टेप 2: OTP वेरिफाई करके कैंसिल करें
POST /booking/:bookingId/cancel/verify
Body: {
  "otp": "123456",
  "cancellationReason": "प्लान चेंज हो गया"
}
```
